### 主对话合并注意事项

1. **#1+#2 必须一起合并**：app_fixed.py 传 stop_event，detector_fixed.py 接收 stop_event，拆开不工作
2. **#3 安全降级**：mDNS 解析失败自动回退硬编码 IP，即使 #3a 未完成也不会 break
3. **#4+#5 独立合并**：ESP8266 固件改动，不影响 Python 端
4. **#3a 待对话A**：ESP32 mDNS 广播需要帧率优化对话处理 `CameraWebServer_fixed.ino`
5. **#6 独立合并**：notify_fixed.py 新增文件，合并后删除旧 notify.py。API 签名不变（`alarm_notify(channel,level,count)` + `alarm_clear_notify(channel,peak)`），detector.py 无需改动。
6. **#6 冷却默认值可调**：`_COOLDOWN_RED=30` / `_COOLDOWN_YELLOW=60` / `_COOLDOWN_CLEAR=30`（秒），演示时如需频繁触发可临时调小。
7. **#7 向后兼容**：`communication_fixed.py` 保留 `flame_active`/`stm32_connected` 模块级属性（聚合所有设备），现有 `detector.py`/`app.py` 无需改动。合并后新增第三个 STM32 零代码改动。
8. **#7+#7a 联动**：ESP8266 固件用 `DEVICE_ID` 宏拼 topic，Python 端通配符订阅自动发现，两边 topic 格式必须一致（`bishe/99257/{ID}/status|flame|alarm`）。
9. **#7 合并时 app.py 同步改动**：`communication_fixed.py` 的 `tcp_server()` 已改为空函数。合并后 `app.py` 需删除第 292 行 `t_tcp = threading.Thread(target=tcp_server, daemon=True)` 及对应的 `t_tcp.start()`，启动日志也去掉 `TCP Server: 端口 8888` 那行。

## 调试指南

### Fix #1+#2 — 连接去重

**验证启动**：Flask 日志中同一秒不应出现两个 `/video_feed` 请求。

**主动测试**：浏览器打开页面后按 F5 刷新，Flask 日志应显示旧连接和新连接各一行，无堆积。

**压力测试**：页面跑 10 分钟，期间操作仪表盘按钮、改阈值。`/dashboard` `/control` 均有响应 → 连接池未耗尽 → 修复生效。

**如果仍卡死**：在 `detector.py` 的 `generate_frames()` 中 stop_event 检查处加临时日志：
```python
if stop_event is not None and stop_event.is_set():
    print("🔌 旧连接已踢，退出生成器")
    return
```
看不到这句 → `app.py` 的 `_active_feed_stop.set()` 未执行 → 检查全局变量是否正确传递。

### Fix #3 — mDNS（等 #3a 完成后测试）

**成功日志**：
```
✅ mDNS 解析 esp32-cam.local → 192.168.x.x
✅ ESP32-CAM 视频流已连接 (HTTP raw)
```

**失败降级日志**：
```
⚠️ mDNS 解析失败，回退硬编码 IP: http://192.168.139.183:81/stream
```

**Windows 注意**：mDNS 需要 Bonjour 服务。解析一直失败时：
- 安装 iTunes 或 Bonjour Print Services
- 或改用 `zeroconf` 库（`pip install python-zeroconf`）

**条件**：PC 和 ESP32-CAM 必须在同一局域网。

### Fix #4+#5 — ESP8266 非阻塞 + 重连

**LED 行为**：
| 阶段 | LED |
|------|-----|
| 上电等待 WiFi | 常亮 |
| WiFi 已连 | 慢闪（500ms） |
| MQTT 已连 | 快闪（200ms） |
| 收到 MQTT 消息 | 短暂灭一下（60ms），不阻塞 |
| WiFi 断开 | 常亮，自动重连 |

**重连测试**：关 WiFi 路由器 → LED 变常亮 → 30s 后开路由器 → ESP8266 自动重连。通过 broker `bishe/99257/status` 主题观察 online/offline 切换。

**退避验证**：反复断连时，重连间隔应为 2s → 4s → 8s → 16s → 32s → 60s（封顶）。连上后重置回 2s。

**编译要求**：Arduino IDE 需安装 PubSubClient 库。`min()` 是 Arduino.h 内置宏，无需额外 include。
