# 第4课：联动决策引擎 — coordinated_decision()

## 这段代码解决什么问题

三个通道各自检测到了人数和报警等级，但**怎么联动**？
- 如果通道A着火了，还让人从A走？
- 如果三个通道都挤满了，推荐哪个出口？
- 多个STM32设备各自绑不同通道，怎么发不同指令？

## 四策略体系

```python
recommended_exit = {
    'exits': ['B', 'C'],        # 推荐出口列表
    'strategy': 'guided',       # 策略名
    'saturations': {'A': 0.8, 'B': 0.3, 'C': 0.4},  # 饱和度
    'message': '推荐从出口B（侧门）通行，当前饱和度30%'
}
```

| 策略 | 触发条件 | 逻辑 |
|------|---------|------|
| `all_clear` | 所有通道 lv=0 且无火灾 | 无需引导，全部安全 |
| `guided` | 有安全通道 + 有通道报警/拥挤 | 排除火灾→按饱和度排序推荐 |
| `degraded` | 所有安全通道饱和度都>1.0 | 分批通行，所有门都接近饱和 |
| `emergency` | 所有通道都有火灾 | 紧急疏散，无安全出口 |

## 饱和度 = count / threshold_warn

为什么用 warn 而不是 red 做分母？
- red 是"危险"线，warn 是"开始拥挤"线
- 饱和度 0.5 = 通道承载能力用了一半
- 饱和度 1.0 = 开始拥挤
- 饱和度 >1.0 = 超拥挤

用饱和度排序替代绝对人数排序——A 通道 5 人（阈值12，饱和度 0.42）vs B 通道 4 人（阈值 5，饱和度 0.8），应该推荐 A，因为 B 更接近它的承载上限。

## 决策流程 (detector.py:209-351)

```python
def coordinated_decision():
    with coord_lock:  # 全局锁，避免多线程同时决策
        # 1. 快照所有通道状态
        snap = {}
        for ch in CHANNELS:
            with channel_locks[ch]:
                st = channel_state[ch]
                # 暂停的通道 count/alarm_level 归零（不发过期数据）
                if not channel_active.get(ch):
                    snap[ch] = {'count': 0, 'alarm_level': 0, 'fire': st['fire']}
                else:
                    snap[ch] = {'count': st['count'], 'alarm_level': st['alarm_level'],
                                'fire': st['fire']}

        # 2. 补充物理火焰状态
        for ch in CHANNELS:
            dev_id = get_channel_device(ch)  # 查绑定
            if dev_id:
                dev = communication.devices.get(dev_id, {})
                if dev.get('online') and dev.get('flame'):
                    snap[ch]['fire'] = True  # 物理火焰覆盖

        # 3. 计算安全出口（排除火灾通道）
        safe = [ch for ch in CHANNELS if not snap[ch]['fire']]
        if not safe:
            strategy = 'emergency'
        else:
            # 按饱和度排序
            saturations = {ch: snap[ch]['count'] / channel_state[ch]['threshold_warn']
                          for ch in CHANNELS}
            safe_sorted = sorted(safe, key=lambda ch: saturations[ch])
            # ... 选 guided 或 degraded ...

        # 4. 为每个绑定设备生成 STM32 指令
        for dev_id, ch in device_bindings.items():
            if not communication.devices.get(dev_id, {}).get('online'):
                continue
            fire = snap[ch]['fire']
            lv = 2 if fire else snap[ch]['alarm_level']
            buz = 1 if lv >= 1 else 0
            servo = 1 if lv >= 2 else 0

            msg = f"LV:{lv},BUZ:{buz},SERVO:{servo}"
            communication.mqtt_send_to(dev_id, msg)  # 定向发送

        # 5. 更新全局状态
        servo_open = any(servo=1)
        buzzer_on = any(buz=1)
        recommended_exit = {...}

        # 6. MQTT 广播 SIG 消息（仪表盘用）
        sig = f"STR:{strategy},REC:{exits},SAT:{saturations}"
        broadcast(sig)
```

## STM32 指令格式

```
LV:0,BUZ:0,SERVO:0   →  正常，全关
LV:1,BUZ:1,SERVO:0   →  黄色预警，蜂鸣器响，舵机不动
LV:2,BUZ:1,SERVO:1   →  红色报警，蜂鸣器+舵机开门
```

`coord_lock` 节流 0.3s（每线程最多每 0.3s 触发一次），且 `mqtt_send_to` 内部有 0.5s 的 per-device 节流，防止 MQTT broker 被刷爆。

## 你答辩时怎么说

> "联动决策引擎每 0.3 秒拍一次快照，看三个通道各自的人数、报警等级、火灾状态。核心逻辑就两步：第一步排除着火通道从安全出口里选，第二步按饱和度排序推荐。饱和度用的是 count 除以预警阈值，反映的是'拥挤程度'而非绝对人数。最终为每个绑定的 STM32 设备生成独立的 LV:BUZ:SERVO 指令，通过 MQTT 定向下发。"
