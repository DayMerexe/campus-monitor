## 三大核心数据结构

```python
# 1. 通道状态 — detector.py:31
# 类型: dict[str, dict]
channel_state = {
    "A": {
        "frame": None,          # np.ndarray | None — 当前帧图像
        "count": 0,             # int — YOLO识别的人数
        "alarm_level": 0,       # int — 0=正常, 1=黄色预警, 2=红色报警
        "alarm_active": False,  # bool — 当前是否处于报警状态
        "fps": 0.0,            # float — 实际检测帧率
        "fire": False,          # bool — 该通道是否检测到火焰
        "threshold_red": 20,   # int — 红色报警阈值
        "threshold_warn": 12,  # int — 黄色预警阈值
        "consecutive": 0,      # int — 防抖计数器
        "monitoring_start": None, # str | None — 通道激活时的ISO时间戳
    },
    "B": {...},  # 结构同上
    "C": {...}   # 结构同上
}

# 2. 设备状态 — communication.py:25
# 类型: dict[str, dict]
devices = {
    "stm32_01": {"online": True, "flame": False},
    "stm32_02": {"online": False, "flame": False}
}
# MQTT 通配符订阅 bishe/99257/+/status|flame 自动发现新设备

# 3. 设备绑定 — detector.py:96
# 类型: dict[str, str]
device_bindings = {
    "stm32_01": "A",   # stm32_01 绑定 → 通道A
    "stm32_02": "B"    # stm32_02 绑定 → 通道B
}
```

> 为什么全用字典？3通道+2设备，字典最简洁。动态增减设备直接用 `devices["stm32_03"] = {...}`，前端 JSON 天然对应 JS 对象。

## 三者关系

```
devices["stm32_01"].online  →  设备是否在线
devices["stm32_01"].flame   →  火焰传感器状态
    ↓
device_bindings["stm32_01"] = "A"  →  这个设备管通道A
    ↓
channel_state["A"]["count"]  →  通道A当前人数
channel_state["A"]["fire"]   →  = devices[绑定设备].flame OR 模拟按钮
```

## 启动流程

```python
# app.py:304-315
init_db()          # 1. 建表 + 列迁移
mqtt_init()        # 2. 连接 MQTT broker，订阅通配符话题
for ch in ['A','B','C']:
    Thread(detect_loop, args=(ch,), daemon=True).start()  # 3. 启动3个检测线程
time.sleep(2)      # 4. 等线程就绪
app.run(host='0.0.0.0', port=5000)  # 5. Flask 启动
```

三个检测线程相位错开 16.7ms 启动（每线程启动后先 sleep 各自的偏移），避免三路 YOLO 同时抢 GPU。
