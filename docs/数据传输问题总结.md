# 数据传输问题总结

## 涉及的数据通道

| 通道 | 协议 | 路径 | 方向 |
|------|------|------|------|
| 视频流 | HTTP MJPEG | ESP32 → Flask `/video_feed` → 浏览器 `<img>` | 单向 |
| 仪表盘 | HTTP JSON | 浏览器 ↔ Flask `/dashboard` | 双向 |
| AI 检测 | MQTT | Python → broker → ESP8266 → STM32 | 单向 |
| 火焰应急 | MQTT | STM32 → ESP8266 → broker → Python | 单向 |
| 手动控制 | HTTP POST | 浏览器 → Flask `/control` `/set_threshold` | 单向 |

---

## 问题 1：浏览器 HTTP 连接池耗尽（最严重）

### 现象
- 页面运行一段时间后所有 HTTP 请求卡死
- Flask 日志不再出现新请求（无 `POST /control`、`GET /dashboard`）
- MQTT 仍然在线（独立 TCP 连接不受影响）
- 同一秒出现两个 `/video_feed` 请求

### 根因
1. 浏览器对同域名 HTTP/1.1 最多 6 个并发连接
2. 浏览器判定 MJPEG 流"卡住" → 关闭旧 TCP 连接 → 开新连接
3. Flask `threaded=True` 为每个请求创建线程，旧线程的 `generate_frames()` 不会立即退出
4. 僵尸线程积累 → 6 个连接池耗尽 → 新请求排队等待 → 页面完全卡死
5. 与摄像头是否在线无关 — `generate_frames()` 无摄像头也发占位图维持连接

### 已尝试的修复
- 三个轮询接口合并为 `/dashboard`（减少 HTTP 连接数）
- `generate_frames()` 固定 200ms 发帧 + 时间戳水印（防止浏览器判为卡死）
- 效果：大幅改善但仍偶发

### 建议修复（未实施）
- `/video_feed` 路由限制同时只有 1 个活跃连接，新连接来踢旧连接
- 或者用 `threading.Event` 做连接存活信号，`generate_frames()` 检测客户端断开后主动退出

## 问题 2：MQTT 报警从不触发（ALARM 始终为 0）

### 现象
- 检测到的人数已超过阈值，但 MQTT 广播的 ALARM 始终为 0
- 串口日志显示 `COUNT:2,ALARM:0` 而不会变 `ALARM:1`

### 根因
防抖算法使用单一计数器：`target == old_level` 时立即清零 `consecutive`。
人数在 1↔2 之间波动时，计数器永远达不到 3 帧确认阈值。

### 修复（已实施）
对称防抖：两个独立计数器
- `consecutive` — 正向，连续 N 帧偏离当前等级才触发切换
- `normal_frames` — 反向，连续 N 帧回到当前等级才重置正向计数器
- 切换后 3 秒锁定防止抖动

详见 `detector.py` 第 118-160 行。

## 问题 3：detect_loop 线程崩溃（DB 缺少 level 列）

### 现象
- 展示有很多人的图片后系统卡死
- 日志：`sqlite3.OperationalError: table alarm_events has no column named level`

### 根因
- 旧数据库在添加 `level` 列之前创建
- `CREATE TABLE IF NOT EXISTS` 只建新表，不迁移已有表结构
- `start_alarm()` 写入 `level` 列时崩溃，`detect_loop` 线程死亡
- 视频流和 MQTT 也随之停止

### 修复（已实施）
- `init_db()` 中 `PRAGMA table_info` 检查 + `ALTER TABLE ADD COLUMN` 自动迁移
- `start_alarm()` 和 `end_alarm()` 调用包 `try/except`，写库失败不影响主循环

## 问题 4：ESP8266 MQTT 稳定性

### 已识别但未修复
- `callback()` 中调用 `delay(30)` 阻塞主 loop，每次 MQTT 消息阻塞 60ms
- 若消息频繁，可能阻塞 keepalive ping 导致 broker 断开
- MQTT 重连机制未加固

### 涉及文件
- `Arduino_camera/ESP8266_MQTT/ESP8266_MQTT.ino`

---

## 问题 5：ESP32-CAM WiFi 连接不稳定

### 现象
- 摄像头偶尔断连，Python 端日志 `⚠️ 无法连接摄像头`
- IP 地址变化（DHCP）：从 192.168.4.183 变为 192.168.139.183

### 当前处理
- `detect_loop()` 每次断连后 5 秒重试
- URL 硬编码在 `detector.py` 中 `ESP32_CAM_URL`

### 建议改进（未实施）
- ESP32 固件设置静态 IP
- 或 Python 端用 mDNS 发现（`esp32-cam.local`）

## 数据传输架构总览（现状）

```
ESP32-CAM ──HTTP MJPEG──→ Python/detector.py ──Flask──→ 浏览器
                              │
                              ├──MQTT──→ broker ──→ ESP8266 ──UART──→ STM32
                              │
                              └──SQLite (data.db)

STM32 ──UART──→ ESP8266 ──MQTT──→ broker ──→ Python/tcp_server.py
                                                  │
                                                  └──Flask──→ 浏览器

浏览器 ──HTTP──→ Flask /dashboard /control /set_threshold
```
