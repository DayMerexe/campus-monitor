# 系统架构

## 通信协议

```
PC → MQTT(broker-cn.emqx.io) → ESP8266 → USART2 → STM32:  "COUNT:X,ALARM:Y\n"
STM32 → USART2 → ESP8266 → MQTT(bishe/99257/flame) → PC: "FLAME:1\n" / "FLAME:0\n"
```

- MQTT broker: `broker-cn.emqx.io:1883`
- 主题: `bishe/99257/alarm`（下行）, `bishe/99257/status`（心跳）, `bishe/99257/flame`（火焰上行）
- ESP8266 遗嘱消息: 断线自动发 `offline`，上线发 `online`
- ESP8266 ↔ STM32: USART2, 115200 8N1
- STM32 USART1: 调试预留 (PA9/PA10)

## 三级报警

| 等级 | 触发条件 | 输出 |
|------|---------|------|
| 0 正常 | 人数 ≤ warn | 全灭 |
| 1 黄色 | warn < 人数 ≤ red | 黄灯闪烁 |
| 2 红色 | 人数 > red | 红灯+蜂鸣器+黄灯 |

- 默认阈值: red=5, warn=3（Web 可调）
- 报警防抖: 连续3帧确认，状态切换后锁定3秒
- 火焰报警优先级最高，不被 MQTT 覆盖

## 双输入通道

- **通道1（远程AI）**：ESP32-CAM → PC YOLOv8 → MQTT → ESP8266 → STM32
- **通道2（本地应急）**：火焰传感器 → STM32 直接响应（不依赖网络，优先级最高）

## 关键实现细节

- **ESP32-CAM 视频流**: HTTP raw 直读 MJPEG（不用 cv2.VideoCapture，FFmpeg 解析不兼容）
- **YOLO**: `yolov8n.pt`，帧缩小到 320×240 推理，框坐标按比例映射回原图
- **舵机控制**: 直接寄存器操作 TIM3（HAL_TIM 驱动文件缺失），非阻塞状态机
  - CCR1: 250=正转全速, 750=停止, 1250=反转全速, 持续1200ms
- **火焰防抖**: 100ms 周期，3帧确认，防止误触发
- **手动报警竞态修复**: 手动报警期间自动广播也发 ALARM:2，防止被 ALARM:0 覆盖
- **`import communication`**: 必须用模块引用而非 `from import`，否则 stm32_connected/flame_active 是值快照

## 应用场景：教学楼多出口联动疏散

### 场景描述

教学楼每层一个主出口通道（A/B/C），各部署摄像头 + 舵机闸门 + 蜂鸣器。系统实时监测三通道人流，当某通道拥挤时联动引导人群到安全出口，防止踩踏事故。

### 运行流程

| 阶段 | 触发条件 | 仪表盘 | STM32 硬件 |
|------|---------|--------|-----------|
| 正常通行 | A/B/C 人数均低 | 三通道 🟢，折线图低位 | 全灭 |
| 黄色预警 | 某通道人数接近阈值 | ⚠️ 弹窗建议疏导，该通道 🟡 闪烁 | 蜂鸣器短促提醒 |
| 红色报警 | 某通道超阈值 | 🔴 该通道标记，⭐ 推荐人数最少的安全通道 | 舵机打开（引导疏散）+ 蜂鸣器持续 |
| 火灾应急 | 火焰传感器触发/模拟按钮 | 🔥 该通道标记危险，强制排除在推荐外 | 红灯+蜂鸣+舵机持续开 |

### 联动决策逻辑

```
collect A/B/C: {count, alarm_level, fire}
safe = 排除 fire=true 的通道
if safe 为空 → 全部危险，不推荐
else → 推荐 safe 中 count 最小的通道 ⭐
任何通道 red → 舵机开；全部 green/yellow → 舵机关
火焰传感器固定分配给通道 A（实物限制）
```

### 多场景模拟方案（待实现）

实物只有 1 个 ESP32-CAM、1 个舵机、1 个火焰传感器。用 MP4 视频文件模拟 3 路输入：

| 组件 | 模拟方式 | 数量 |
|------|---------|:--:|
| 摄像头 | 3 个 MP4 文件替代 ESP32-CAM 实时流 | 3 路虚拟 |
| 舵机 | 共享 1 个物理舵机，多场景 OR 逻辑控制 | 1 个共享 |
| 火焰传感器 | 固定分配给通道 A，B/C 通过模拟按钮触发 | 1 个 + 按钮 |
| 蜂鸣器 | 共享 1 个，任一场景报警即响 | 1 个共享 |

**仪表盘**：3 个视频窗口 + 独立人数/状态灯 + 联动推荐面板 + 火灾模拟按钮。每个场景有独立的虚拟舵机状态图标（实物共享但逻辑独立）。

**论文设计点**：单 MCU 集中控制多场景联动，体现"低成本、可扩展"的系统架构思想。
