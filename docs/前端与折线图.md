## 任务描述

### 问题 1：前端 UI 优化

**现象：**
- 前端整体功能齐全但细节粗糙
- 视频源切换时 MJPEG URL 输入体验不佳
- 按钮状态反馈不够直观
- 移动端/小屏适配可改进

**涉及文件：**
- `campus_monitor/templates/index.html`（单文件，全部前端逻辑）

### 问题 2：折线图与三通道灵活启停不匹配

**现象：**

1. **通道可选启停，但折线图永远三条线**：三通道可以任意打开/关闭，但 chart.js 始终创建三条 dataset，关闭的通道线还在图上（残留旧数据或归零线）。
2. **启动时折线图已有历史记录**：页面打开时用 `PAGE_OPEN_TIME` 过滤 `since` 参数，但 DB 中旧数据仍然存在，关闭再开的通道会带出旧记录。
3. **X 轴时间戳用 A 通道的**：`chart.data.labels` 取 `chHist.A` 的时间，假设三通道时间对齐——但通道是独立启动的，B/C 可能比 A 晚开、早关、或根本没开过。
4. **通道中途关闭后再开，旧线去哪了**：无明确设计。关闭通道的折线是保持、清空、还是灰化？
5. **折线图不能反映系统灵活复杂的使用情况**：比如 A 监控了 10 分钟，B 在第 3 分钟打开、第 8 分钟关闭，C 全程未开——折线图应该清晰呈现这种"各通道独立生命周期"。

**根因：**
折线图设计时假设"三通道一起启动、一起运行、永不停机"，现在系统已支持每通道独立启停+独立视频源切换，折线图没有跟进。

**涉及文件：**
- `campus_monitor/templates/index.html`（chart.js 部分，约 L543-573 创建，L860-871 更新）
- `campus_monitor/db.py`（`get_channel_history` 返回数据格式）
- 可能需要 `campus_monitor/app.py`（新增 API 提供通道时间线数据）

## 任务总结

### 做了什么
前端 UI 全面优化 + 折线图重设计，分 4 个分支完成。折线图从"硬编码三条线"改为动态数据集精确匹配各通道独立启停生命周期，配套 Chart.js 配置优化（spanGaps、秒对齐、monitoring_start 服务端过滤）。

### 踩了什么坑 / 怎么解决的
| 坑 | 原因 | 解决方法 |
|----|------|---------|
| 通道关闭后折线图高度塌陷 | `.chart-box` 用 `min-height` 而非固定高度，canvas 高度随数据集动态变化 | 改为 `height: 280px` + `overflow: hidden` |
| 关闭再开启通道出现"旧记录" | 客户端 `PAGE_OPEN_TIME` 过滤不可靠，DB 数据跨越开关周期 | 改为服务端 `monitoring_start` 追踪，前端直接读服务端时间戳过滤 |
| 三通道折线 X 轴不对齐 | 各自独立时间戳，同一秒差几百毫秒 | `timestamp.split('.')[0]` 秒对齐 |
| 折线断断续不连 | 通道暂停期间无数据点 | `spanGaps: true` |

### 留给后续的注意事项
- 前端是单文件 `templates/index.html`，约 1000+ 行，后续维护建议拆分 JS/CSS
- Chart.js 配置对数据量敏感，DB 写入现在是 1s 间隔，降低频率会影响折线平滑度
