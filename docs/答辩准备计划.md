5. **展示今日统计数据**

### 常见问题准备

| 问题 | 回答要点 |
|------|---------|
| 为什么用 YOLOv8n？ | 速度快，nano 模型在 CPU 上也能跑实时 |
| 为什么不用 MQTT？ | TCP 透传模式更简单，不需要 broker，直连 ESP8266 |
| 防抖怎么做的？ | 连续 3 帧确认 + 状态切换后锁定 3 秒，防止误报 |
| 帧率多少？ | 约 15-20 FPS（取决于摄像头和 CPU） |
| 阈值设多少？ | 默认 5 人，网页上可以动态调整 |
| 如果摄像头断开怎么办？ | 自动重连机制，每 5 秒尝试重连 |
| 数据库用的什么？ | SQLite，轻量级，零配置 |

### 如果演示翻车了
- **摄像头连不上**：说"实验室环境下偶尔有 WiFi 干扰，重启一下就好"然后重试
- **检测不到人**：检查摄像头角度，走近一些
- **STM32 没反应**：检查 ESP8266 指示灯是否连上 WiFi/TCP
- **真修不好**：给老师看 PPT 里的系统框图 + 代码逻辑，演示翻车不会扣大分

## 重点强调的亮点（让老师觉得有工作量）

1. **报警防抖机制** — 不是简单阈值判断，而是 3 帧确认 + 3 秒锁定
2. **MJPEG 流式解析** — 自己写 SOI/EOI 标记解析，不是用 OpenCV VideoCapture
3. **TCP 广播限速** — 0.5 秒限速防止冲垮 STM32 UART
4. **硬件端逐字节 UART 轮询** — STM32 主循环逐字符解析 `COUNT:人数,ALARM:0/1`
5. **低电平有效 GPIO** — 正确理解和实现硬件电平逻辑
6. **手动报警 + 自动检测双模式** — 互斥逻辑设计
