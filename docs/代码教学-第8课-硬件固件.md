# 第8课：硬件固件 — STM32 / ESP8266 / ESP32-CAM

## 这段代码解决什么问题

软件再聪明，最终要驱动物理硬件——开门、响蜂鸣器、亮灯。三块芯片各司其职。

## ESP32-CAM：摄像头 (CameraWebServer.ino)

```
作用：提供 MJPEG 实时视频流
配置要点：
  - 传感器 OV2640，分辨率 QVGA (320×240)
  - XCLK 30MHz（关键！20MHz→2fps, 30MHz→20+fps）
  - JPEG quality=8, brightness=-1, contrast=-1
  - grab_mode = CAMERA_GRAB_LATEST（永远取最新帧）
  - WiFi 强制无省电模式（esp_wifi_set_ps(WIFI_PS_NONE)）
  - PWDN 引脚上电硬复位 + SCCB 传感器软复位

视频流获取：
  http://ESP32-CAM-IP:81/stream → MJPEG 边界分隔的 JPEG 帧流
  Python 端用持久 HTTP 连接 + raw.read() 逐帧读取
```

## ESP8266：MQTT↔UART 桥接 (ESP8266_MQTT_multi.ino, 225行)

```
              MQTT                          UART (115200 8N1)
  [云 broker] <====> [ESP8266 ESP-01] <========================> [STM32]
                    DEVICE_ID 宏区分设备
                    stm32_01 / stm32_02

上电流程:
  1. WiFi 连接（无限重试，指数退避 2s→60s）
  2. MQTT 连接（无限重试，LWT 遗嘱 = "offline"）
  3. 连接成功 → publish "online" to status topic
  4. subscribe alarm topic（服务器指令通道）
  5. 进入主循环

主循环 (loop):
  WiFi/MQTT 重连检查
  ← Serial.readStringUntil('\n') — 读 STM32 发来的行
    → publish to flame topic
  → MQTT callback — 收到服务器 alarm 消息
    → Serial.write(payload) — 原样转发给 STM32

LED 状态指示:
  常亮 = 启动/WiFi连接中
  慢闪 (500ms) = WiFi OK, MQTT连接中
  快闪 (200ms) = MQTT 已连接
  短闪 = 收到消息
```

## STM32：执行终端 (main.c, 350行)

### 外设分配

| 外设 | 引脚 | 功能 | 电平 |
|------|------|------|------|
| USART2 | PA2/PA3 | 与ESP8266通信 | 115200 8N1 |
| TIM3 CH1 | PA6 | SG90舵机PWM | 50Hz, CCR调控 |
| GPIO | PB8 | 蜂鸣器 | 高有效 |
| GPIO | PA0 | 火焰传感器DO | 低=检测到火焰 |
| GPIO | PE5 | 黄色LED DS1 | 低有效 |
| GPIO | PB5 | 红色LED DS0 | 低有效 |

### 初始化序列

```
HAL_Init → 系统时钟64MHz → GPIO → USART1/2
→ PB8 蜂鸣器输出
→ PA0 火焰传感器输入(上拉)
→ TIM3 CH1 PWM 50Hz, CCR1=750 (1.5ms = 舵机停止)
→ LED全灭 → 蜂鸣器关
→ 红LED闪3次（启动指示）
→ 等4秒（ESP8266初始化时间）
→ 清USART2缓冲区
→ 黄LED闪2次（进入主循环）
```

### 主循环 (100Hz)

```c
while (1) {
    servo_tick();  // 非阻塞舵机状态机

    // 火焰传感器轮询 — 100ms间隔
    if (now - last_flame >= 100) {
        if (HAL_GPIO_ReadPin(GPIOA, GPIO_PIN_0) == 0) {  // 低电平=火
            flame_debounce++;
            if (flame_debounce >= 3) {  // 3次确认
                flame_alarm = 1;
                set_outputs(2);  // 红+黄LED+蜂鸣器
                servo_open_gate();
                printf("FLAME:1\n");  // → ESP8266 → MQTT → Python
            }
        } else {
            flame_debounce--;
            if (flame_debounce <= 0) {
                flame_alarm = 0;
                restore_mqtt_state();  // 恢复到MQTT上次指令
                printf("FLAME:0\n");
            }
        }
    }

    // MQTT 消息解析 — 逐字节读USART2
    while (USART2->SR & UART_FLAG_RXNE) {
        char c = USART2->DR;
        rx_buf[rx_idx++] = c;
        if (c == '\n') {
            rx_buf[rx_idx] = '\0';
            int lv, buz, servo;
            if (sscanf(rx_buf, "LV:%d,BUZ:%d,SERVO:%d", &lv, &buz, &servo) == 3) {
                mqtt_lv = lv;
                mqtt_servo = servo;
                if (!flame_alarm) {  // 火焰优先，不覆盖
                    set_outputs(lv);
                    if (servo) servo_open_gate();
                    else servo_close_gate();
                }
            }
            rx_idx = 0;
        }
    }
}
```

### 舵机控制（非阻塞状态机）

```
360度 SG90 舵机:
  CCR=250  → 全速正转（开门）
  CCR=750  → 停止
  CCR=1250 → 全速反转（关门）

非阻塞: 设置CCR后启动1200ms定时器，到时间自动切回750(停止)
         不占用主循环，火焰传感器仍能轮询
```

## 端到端数据流

```
前端点 "🔥 模拟A通道火灾"
  → POST /fire_simulate/A {action:'on'}
  → channel_state['A']['fire'] = True
  → coordinated_decision()
  → snap['A']['fire']=True → 排除A → safe=[B,C]
  → stm32_01 bind A, fire=true → LV:2,BUZ:1,SERVO:1
  → mqtt_send_to("stm32_01", "LV:2,BUZ:1,SERVO:1")
  
  [MQTT broker]
  
  → ESP8266 stm32_01 收到 alarm topic
  → Serial.write("LV:2,BUZ:1,SERVO:1\n")
  
  [UART]
  
  → STM32 USART2 接收
  → sscanf 解析 lv=2, buz=1, servo=1
  → set_outputs(2) → 红LED+黄LED+蜂鸣器
  → servo_open_gate() → CCR1=250 → 1200ms后自动停止

总延迟: < 500ms（MQTT + 串口 + 机械）
```

## 你答辩时怎么说

> "硬件分三层。ESP32-CAM 负责视频采集，30MHz 时钟驱动 OV2640 输出 20+fps 的 MJPEG 流。ESP8266 是通信桥梁，WiFi 连 MQTT broker，UART 连 STM32，双向透传不做处理。STM32 是最终执行端——轮询火焰传感器、解析 MQTT 指令、控制舵机/蜂鸣器/LED。火焰传感器有独立的三帧去抖，且拥有最高优先级——火焰触发时 MQTT 指令不能覆盖。从浏览器点下火灾模拟按钮到舵机转动，整条链路延迟不到半秒。"
