# 第3课：三级报警 + 对称防抖

## 这段代码解决什么问题

YOLO 检测有波动——同一帧可能识别 4 个人，下一帧 6 个，再下一帧又 4 个。如果直接拿 count 跟阈值比，报警灯会疯狂闪烁。这就是"阈值边界抖动"。

## 三级报警定义

| 等级 | 条件 | 输出效果 |
|------|------|---------|
| 0 (正常) | count ≤ threshold_warn | 全灭 |
| 1 (黄色预警) | threshold_warn < count ≤ threshold_red | 黄LED闪烁 |
| 2 (红色报警) | count > threshold_red | 红LED常亮 + 黄LED常亮 + 蜂鸣器响 + 舵机开门 |

默认阈值：red=20, warn=12（每个通道可独立设定）

## 对称防抖算法

```
         count > red 连续3次 → 升到红色
         count > warn 连续3次 → 升到黄色
  level  count ≤ warn 连续3次 → 降到绿色
         count ≤ red 连续3次 → 从红色降到黄色

  状态切换后锁定3秒，期间不接受新的升降级
```

**为什么"对称"重要？** 最初的版本只防升级不防降级，导致：
- 升到红色需要3次确认（不容易误报）
- 降到绿色只要1次（人群一闪就解除）

结果就是报警"秒触秒消"。改对称后升降都需3次确认，稳定多了。

## 关键代码 (detector.py:167-175 + detect_loop内防抖段)

```python
# 1. 判断目标等级
def get_target_level(count, channel):
    with channel_locks[channel]:
        red = channel_state[channel]['threshold_red']
        warn = channel_state[channel]['threshold_warn']
    if count > red:   return 2
    if count > warn:  return 1
    return 0

# 2. 防抖逻辑 (在 detect_loop 内)
target = get_target_level(count, channel)
with channel_locks[channel]:
    st = channel_state[channel]
    current = st['alarm_level']  # 当前实际等级

    if target > current:        # 需要升级 → 累加 consecutive
        st['consecutive'] += 1
        if st['consecutive'] >= ALARM_CONFIRM:  # 3次确认
            st['alarm_level'] = target
            st['consecutive'] = 0
            st['last_state_change'] = now  # 记录切换时间
    elif target < current:      # 需要降级 → 累加 normal_frames
        st['normal_frames'] += 1
        if st['normal_frames'] >= ALARM_CONFIRM:
            st['alarm_level'] = target
            st['normal_frames'] = 0
            st['last_state_change'] = now
    else:                       # 目标=当前 → 重置计数器
        st['consecutive'] = 0
        st['normal_frames'] = 0

    # 3秒锁定
    if now - st['last_state_change'] < ALARM_LOCK:
        continue  # 跳过后续DB写入和MQTT广播
```

## 两个常量

```python
ALARM_CONFIRM = 3   # 需连续3帧确认（约0.15秒 @20fps）
ALARM_LOCK = 3.0    # 状态切换后锁定3秒
```

## 状态图

```
     ┌──────────┐   count>red×3   ┌──────────┐
     │  GREEN   │ ───────────────> │   RED    │
     │  lv=0    │                  │  lv=2    │
     └──────────┘                  └──────────┘
          ↑  ▲                        │  │
 count>warn×3 │  count≤warn×3  count≤red×3 │  count>red×3
          │  │                        ↓  ↓
     ┌──────────┐                  ┌──────────┐
     │  YELLOW  │ <─────────────── │   RED    │
     │  lv=1    │  count≤red×3    │  lv=2    │
     └──────────┘                  └──────────┘
```

关键：每次切换后锁定3秒，防止在阈值边界反复横跳。

## 手动报警 (app.py: /control)

```python
# 手动触发红色报警（与火灾同级 lv=2）
detector.manual_alarm_active = True  # 标识位
# coordinated_decision 中：
lv = 2 if (fire or manual_alarm_active) else bound_alarm
```

手动报警不是覆盖所有通道——它是一个独立的全局标记，在联动决策中和火灾同级处理。

## 你答辩时怎么说

> "为了防止人数波动导致报警灯闪烁，我们用了对称防抖——升级需要连续3帧确认，降级同样需要连续3帧，切换后有3秒锁定。这比单纯'count > 阈值就报警'稳定得多，28个记录在案的问题中这个是前几个发现的。"
