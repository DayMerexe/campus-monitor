# 数据库优化

## 任务描述

### 问题：数据库设计过于简易

**现象：**

1. **无日期分类**：所有记录混在 `detection_records` 和 `alarm_events` 两张表里，无按日/周/月的分区或归档。查"上周三 A 通道的数据"需要全表扫 timestamp 字符串。
2. **无数据清理**：数据无限增长，SQLite 单文件越来越大。在线运行几周后查询 `get_channel_history` 会变慢。
3. **无聚合统计**：只有原始逐条记录。查"每天峰值人数"、"每小时平均流量"需要每次即时计算，没有预聚合表。
4. **timestamp 存 ISO 字符串**：`datetime.now().isoformat()` 存入 TEXT 列，用 `LIKE '2026-05-17%'` 查当天数据——字符串匹配而非索引范围查询，效率低。
5. **无索引**：表上只有 PRIMARY KEY，`channel` + `timestamp` 的联合查询没有索引。
6. **缺少运行统计表**：比如"系统总运行时长"、"各通道累计监测时长"等仪表盘可能需要的数据无处存储。
7. **折线图查询语义模糊**：`get_channel_history(limit_per_channel=20, since=...)` 返回每通道最近 20 条——如果通道 A 开了 1 小时（120 条记录），通道 B 只开了 2 分钟（4 条），各取 20 条时间跨度的含义不同。

**涉及文件：**
- `campus_monitor/db.py`（全部函数）
- `campus_monitor/detector.py`（`insert_detection`、`start_alarm`、`end_alarm` 调用处，签名可能变化）
- `campus_monitor/app.py`（API 路由调用 `get_channel_history`、`get_recent_records`、`get_alarm_events`、`get_today_stats`）
