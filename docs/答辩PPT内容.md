## 第3页：项目背景与研究意义

**校园安全痛点**：
- 高校人员密集场所（食堂、体育馆、教学楼等）缺乏实时人流监测手段
- 传统人工计数效率低、误差大
- 突发事件（如火灾、地震）时无法快速判断疏散需求

**研究目标**：
- 基于 AI 视觉识别技术，实现校园重点区域的人流量实时监测与自动报警
- 检测结果通过 Web 仪表盘可视化展示
- 超过阈值时自动驱动硬件报警（LED + 蜂鸣器）

## 第4页：系统总体架构

**数据流向**：
```
ESP32-CAM → HTTP MJPEG 视频流 → PC (YOLOv8 + Flask)
    ↓
Flask Web → 浏览器实时展示
    ↓
TCP 协议 :8888 → ESP8266 (WiFi桥) → UART → STM32 → LED / 蜂鸣器
```

**三大子系统**：
1. 视频采集与 AI 检测子系统（ESP32-CAM + YOLOv8）
2. Web 可视化子系统（Flask + Chart.js）
3. 报警执行子系统（TCP + ESP8266 + STM32）

## 第5页：硬件设计与实现

**STM32F103ZET6 控制板**：
- 主频 64MHz，HAL 库，Keil MDK-ARM 开发
- USART1（调试串口）+ USART2（ESP8266通信）+ GPIO（LED/蜂鸣器）

**ESP32-CAM 摄像头模块**：
- AI-THINKER 型号，OV2640 传感器，支持 MJPEG 推流
- 分辨率 QVGA（320×240），XCLK 20MHz

**ESP8266 ESP-01S WiFi 模块**：
- AT 固件，透明传输模式（CIPMODE=1）
- 作为 TCP 客户端连接 PC:8888

**接线关系**：
```
ESP32-CAM ← WiFi → PC ← TCP → ESP8266 ← UART → STM32
```

**STM32 引脚分配**：

| 引脚 | 外设 | 说明 |
|------|------|------|
| PA2/PA3 | USART2 | 与 ESP8266 通信（115200 8N1） |
| PA9/PA10 | USART1 | CH340 调试串口 |
| PE5 | 黄灯 | 低电平亮，调试指示用 |
| PB5 | 红灯 | 低电平亮，报警指示用 |
| PB8 | 蜂鸣器 | 高电平响 |

**ESP8266 接线**：

| STM32 | ESP8266 |
|-------|---------|
| PA2 (TX) | → RX |
| PA3 (RX) | → TX |
| 3.3V | → VCC、CH_PD(EN)、GPIO0 |
| GND | → GND |

> ⚠ ESP8266 需独立 3.3V 供电（峰值电流 300mA+），不要仅靠 STM32 板载引脚

## 第6页：软件设计与实现

**Python 后端**（campus_monitor/ 模块化架构）：

| 文件 | 功能 |
|------|------|
| app.py | Flask 入口，6 个 REST API 路由 |
| detector.py | HTTP 直读 MJPEG + YOLOv8 推理 + TCP 广播 + DB 写入 |
| db.py | SQLite 数据库层（检测记录 + 报警事件两张表） |
| communication.py | TCP Server 监听 8888 端口，管理客户端列表 |

**Web 前端**（templates/index.html）：
- Chart.js 折线图实时展示人数变化趋势
- 毛玻璃风格仪表盘，2 秒自动刷新
- 支持动态调节阈值、手动报警/解除
- 报警历史记录表格

**STM32 固件**（stm32_serial_led/Src/main.c）：
- AT 初始化 → 透明传输模式 → sscanf 逐行解析 → GPIO 控制

## 第7页：YOLOv8 行人检测

**模型选型**：YOLOv8n（nano），轻量级，可在 CPU 上实时运行

**检测流程**：
1. HTTP 直读 MJPEG 流（替代 cv2.VideoCapture，更稳定）
2. 查找 JPEG 起始标记 SOI（\xff\xd8）和结束标记 EOI（\xff\xd9）切帧
3. cv2.imdecode 解码为 OpenCV 图像
4. 缩小到 320×240 推理，坐标按比例映射回原图画框
5. 只检测 person 类别（COCO 类 ID=0）

**报警防抖机制（关键设计）**：
- 连续 3 帧超过阈值 → 触发报警（防止单个误检）
- 连续 3 帧低于阈值 → 解除报警
- 状态切换后锁定 3 秒 → 防止频繁震荡

**通信协议**：`COUNT:人数,ALARM:0/1`

**其他优化**：
- TCP 广播限速 0.5 秒，防止 STM32 UART 溢出
- DB 写入限速 2 秒间隔
- 手动报警期间暂停自动 TCP 广播

## 第8页：关键技术与选型

**MJPEG 解析方案选型**：
- ❌ cv2.VideoCapture — FFmpeg 解析 multipart 流不稳定
- ✅ HTTP raw 直读 + 手动 SOI/EOI 切帧 — 稳定可靠

**ESP8266 通信模式选型**：
- ❌ 普通模式 — 需解析 +IPD,N: 前缀，处理分片拼接
- ✅ 透明传输模式（CIPMODE=1）— 数据直达，sscanf 直接匹配

**STM32 初始化优化**：
- ESP8266 flash 保存 WiFi 信息，上电自动连接热点
- 去掉 CWMODE/CWQAP/CWJAP 等冗余 AT 指令
- 启动时间从 15 秒缩短到 5 秒

**TCP 稳定性保障**：
- SO_KEEPALIVE + 5 秒超时检测死连接
- 广播时自动清理已断开的客户端
