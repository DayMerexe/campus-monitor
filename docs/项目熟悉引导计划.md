## 第一阶段：理解全貌（10 分钟）

### 一句话概括

> ESP32-CAM 拍摄画面 → YOLOv8 AI 识别画面中的人数 → Flask 网页展示实时画面和数据 → 人数超过阈值时通过 TCP 无线控制 STM32 开发板的 LED 和蜂鸣器报警

### 数据流向

```
┌──────────┐   MJPEG HTTP    ┌──────────┐   JSON REST    ┌──────────┐
│ ESP32-CAM │ ───────────────→ │   PC     │ ←────────────── │ Browser  │
│ (摄像头)   │   视频流         │ Python   │   WebSocket轮询  │ (网页)    │
└──────────┘                  │ 后端     │                └──────────┘
                              │          │
                              │ YOLOv8   │
                              │ 检测人数  │
                              └────┬─────┘
                                   │ TCP :8888
                                   │ "COUNT:3,ALARM:0\n"
                                   ↓
                              ┌──────────┐   UART 115200  ┌──────────┐
                              │ ESP8266  │ ───────────────→ │  STM32   │
                              │ (WiFi桥)  │   透明传输       │ (控制板)  │
                              └──────────┘                 └────┬─────┘
                                                                │
                                                    ┌───────────┼───────────┐
                                                    ↓           ↓           ↓
                                                红灯(LED0)   黄灯(LED1)    蜂鸣器
                                                (报警亮)     (调试指示)    (报警响)
```

## 第二阶段：逐层深入（30 分钟）

### 第 1 层 — 前端界面

**文件**: `campus_monitor/templates/index.html`

**启动后访问** `http://localhost:5000` 看到的就是这个页面。

**布局**（从上到下）：
- **顶栏**：标题、英语副标题、FPS 显示
- **左列**：实时视频流 → 控制栏（阈值设置 + 手动报警按钮）
- **右列**：4 个统计卡片（当前人数 / 报警状态 / 今日检测 / 报警和峰值）→ 折线图
- **报警横幅**：超过阈值时显示红色警告
- **报警历史表格**：记录每次报警的开始时间、结束时间、峰值人数、持续时长

**数据更新方式**：JavaScript 每 2 秒轮询 `/status` 接口刷新统计数字和折线图，每 5 秒刷新报警表格。

> **操作建议**：打开浏览器开发者工具 (F12) → Network 标签，看 `status` / `history` / `alarms` 三个接口的请求和响应。

### 第 2 层 — Flask 后端

**文件**: `campus_monitor/app.py`

6 个路由，功能清晰：

| 路由 | 方法 | 功能 |
|------|------|------|
| `/` | GET | 返回首页 HTML |
| `/video_feed` | GET | 返回 MJPEG 视频流（不断推帧） |
| `/status` | GET | 返回 JSON：当前人数、报警状态、阈值、FPS、今日统计 |
| `/set_threshold` | POST | 修改报警阈值 |
| `/control` | POST | 手动报警/解除（直接 TCP 广播） |
| `/history` | GET | 返回最近 20 条检测记录（供折线图） |
| `/alarms` | GET | 返回报警事件列表 |

**启动流程**（`app.py` 第 81-93 行）：
1. 初始化 SQLite 数据库
2. 启动 `detect_loop` 线程（YOLO 检测循环）
3. 启动 `tcp_server` 线程（监听 ESP8266 连接）
4. 启动 Flask Web 服务（端口 5000）

### 第 3 层 — YOLO 检测引擎

**文件**: `campus_monitor/detector.py`

这是**最核心**的模块，值得逐行理解。

**检测循环** (`detect_loop` 函数)：

```
while True:
    ├── GET http://192.168.4.121:81/stream  (连接摄像头)
    ├── 逐 chunk 读取 HTTP 响应体
    │   ├── 查找 JPEG 起始标记 \xff\xd8
    │   ├── 查找 JPEG 结束标记 \xff\xd9
    │   ├── 截取完整 JPEG → cv2.imdecode 解码
    │   └── 解码成功:
    │       ├── 缩小到 320×240
    │       ├── YOLO 推理 → 检测 person 类
    │       ├── 报警防抖逻辑（3帧确认 + 3秒锁定）
    │       ├── 画框（按比例映射回原图坐标）
    │       ├── TCP 广播给 STM32（限速 0.5 秒）
    │       └── DB 写入（每 2 秒一次）
    └── 连接断开 → 等待 2 秒 → 重连
```

**关键参数**：
- `CONFIDENCE_THRESHOLD = 0.5` — 检测置信度阈值
- `ALARM_THRESHOLD = 5` — 报警人数阈值（可在网页动态修改）
- `ALARM_CONFIRM = 3` — 连续 3 帧超过阈值才触发报警
- `ALARM_LOCK = 3.0` — 状态切换后锁定 3 秒

### 第 4 层 — 数据库

**文件**: `campus_monitor/db.py`

两张表：
- **`detection_records`**：每次检测的记录（时间戳、人数、是否报警、FPS）
- **`alarm_events`**：报警事件（开始/结束时间、峰值人数、持续时长）

数据文件：`campus_monitor/data.db`（SQLite）

### 第 5 层 — TCP 服务器

**文件**: `campus_monitor/communication.py`

- 监听端口 `8888`，等待 ESP8266 连接
- 维护 `tcp_clients` 列表（支持多客户端）
- `tcp_broadcast()` 函数向所有 ESP8266 广播消息，自动清理死连接
- 带 keepalive 和 5 秒超时检测

### 第 6 层 — STM32 固件

**文件**: `stm32_serial_led/Src/main.c`

**初始化序列**：
1. 外设初始化（GPIO、USART1、USART2）
2. 手动初始化 PB8（蜂鸣器引脚）
3. LED 闪烁 3 次 → 启动成功信号
4. 发送 `AT` → 测试 ESP8266 响应
5. 发送 `AT+CIPSTART` → 连接 TCP Server（4 秒等待）
6. 发送 `AT+CIPMODE=1` → 设为透明传输模式
7. 发送 `AT+CIPSEND` → 进入透传
8. 清空 USART2 缓冲区（丢弃 AT 回复残留）
9. 黄灯闪烁 2 次 → 初始化完成

**主循环**：
```c
while (1) {
    // 逐字节轮询接收
    if (HAL_UART_Receive(&huart2, &ch, 1, 1) == HAL_OK) {
        if (ch == '\r') continue;       // 忽略回车
        else if (ch == '\n') {          // 换行 = 一行结束
            rx_buf[rx_idx] = '\0';
            if (sscanf(rx_buf, "COUNT:%d,ALARM:%d", &count, &alarm) == 2) {
                // 控制 GPIO
            }
            rx_idx = 0;                  // 清空行缓冲
        } else {
            rx_buf[rx_idx++] = ch;       // 追加到行缓冲
        }
    }
}
```

**硬件引脚**：
| 引脚 | 外设 | 说明 |
|------|------|------|
| PA9/PA10 | USART1 | CH340 调试串口 |
| PA2/PA3 | USART2 | 与 ESP8266 通信 |
| PE5 | 黄灯 | 调试指示（低有效） |
| PB5 | 红灯 | 报警指示（低有效） |
| PB8 | 蜂鸣器 | 报警声（高有效） |

### 第 7 层 — ESP8266 (ESP-01S)

- 烧录 AT 固件
- 上电自动连接已保存的 WiFi 热点
- 通过 UART (115200 8N1) 与 STM32 通信
- 工作在透明传输模式，TCP 数据直达 STM32 串口
- 供电要求：3.3V / 300mA+（需要独立供电）

### 第 8 层 — ESP32-CAM

- 型号：AI-THINKER
- 固件：Arduino IDE 编译烧录（`Arduino_camera/CameraWebServer/`）
- 功能：拍摄 MJPEG 视频流 → HTTP `:81/stream` 推流
- 同时运行 WiFi AP 热点（`test` / `wxh708023`）供所有设备连接

## 第四阶段：答辩准备要点

### 项目亮点（引导老师关注点）

1. **完整的数据闭环**：摄像 → AI 分析 → Web 展示 → 硬件控制，全链路打通
2. **多设备异构通信**：WiFi (HTTP) + TCP + UART 三种通信方式协同
3. **报警防抖机制**：连续 3 帧确认 + 3 秒锁定，防止误触发
4. **透传模式选型**：对比 `+IPD` 普通模式和透明传输模式，选出最简方案
5. **架构模块化**：Flask 分离为 app/db/detector/communication，易于维护

### 可能的提问

| 问题 | 回答方向 |
|------|----------|
| 为什么用 YOLOv8？ | 精度高、推理快、nano 模型可在 CPU 上实时运行 |
| 为什么不用 MQTT？ | TCP 透明传输更简单直接，适合一对多广播 |
| 帧率上不去怎么办？ | 缩小推理帧 320×240，画质调低，XCLK 调高 |
| 多摄像头如何扩展？ | 当前架构只需增加 ESP32-CAM 并修改 detector 中的 URL |
| 数据可靠吗？ | SQLite 本地存储，支持按日期查询历史记录 |
| 如何部署？ | 单机运行，PC 需连 ESP32-CAM 的 WiFi，启动 app.py 即可 |
