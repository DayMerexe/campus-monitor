# 多场景模拟改造

> 子对话入口文档：将单路 ESP32-CAM 改为 3 路 MP4 视频输入，实现教学楼多出口联动疏散模拟。

---

## 任务描述

将当前单通道检测系统改造为三通道联动系统。**保留现有 ESP32-CAM 实时流作为通道 A**，额外增加 2 路 MP4 视频模拟通道 B/C，实现多场景联动演示。

### 改造目标

| 组件 | 当前 | 目标 |
|------|------|------|
| 视频输入 | 1× ESP32-CAM MJPEG | 通道 A: ESP32-CAM 实时流（保留不动）+ 通道 B/C: 2× MP4 循环播放 |
| 检测线程 | 1× `detect_loop()` | 3× 独立检测线程（每通道独立 YOLO 推理） |
| 仪表盘 | 1 个视频窗口 + 单统计卡片 | 3 个视频窗口 + 每通道独立人数/状态灯 + 联动推荐面板 |
| 报警决策 | 单通道三级报警 | 联动决策：排除火灾通道 → 推荐人数最少安全出口 |
| MQTT 协议 | `COUNT:X,ALARM:Y` | 扩展为多通道 + 推荐出口信息 |
| 火焰传感器 | 固定通道 A（ESP32-CAM 对应位置） | 固定通道 A，B/C 用 Web 按钮模拟触发 |
| 舵机 | 单场景控制 | 共享物理舵机，OR 逻辑（任一红色→开） |
| 蜂鸣器 | 单场景报警 | 共享，任一红色即响 |

### 联动决策逻辑（见 `docs/architecture.md`）

```
collect A/B/C: {count, alarm_level, fire}
safe = 排除 fire=true 的通道
if safe 为空 → 全部危险，不推荐
else → 推荐 safe 中 count 最小的通道 ⭐
任何通道 red → 舵机开；全部 green/yellow → 舵机关
火焰传感器固定分配给通道 A（实物限制）
```

## 测试方法

```bash
# 1. 准备 2 个 MP4 测试视频（行人场景），放到 campus_monitor/videos/
#    通道 A 使用现有 ESP32-CAM 实时流（不可用时自动回退 MP4）
# 2. 启动系统
cd F:\bishe\campus_monitor
/c/Users/DayMer/miniconda3/python.exe app.py

# 3. 浏览器打开 localhost:5000，确认：
#    - 3 个视频窗口均有画面
#    - 每通道独立计数和状态灯
#    - 调高某通道阈值触发报警 → 联动推荐面板更新
#    - 点击火灾模拟按钮 → 对应通道标记为危险，推荐排除
```

验收标准：
- 通道 A ESP32-CAM + 通道 B/C MP4 三路独立推理，帧率 ≥ 10fps/路
- 联动推荐逻辑正确（火灾通道排除 + 推荐人数最少安全出口）
- 仪表盘 3 窗口 + 推荐面板 + 火灾按钮均正常工作
- MQTT 广播包含推荐出口信息
