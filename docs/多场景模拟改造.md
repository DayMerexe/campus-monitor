# 多场景模拟改造

> 子对话入口文档：将单路 ESP32-CAM 改为 3 路 MP4 视频输入，实现教学楼多出口联动疏散模拟。

---

## 任务描述

将当前单通道检测系统改造为三通道联动系统。**保留现有 ESP32-CAM 实时流作为通道 A**，额外增加 2 路 MP4 视频模拟通道 B/C，实现多场景联动演示。

### 改造目标

| 组件 | 当前 | 目标 |
|------|------|------|
| 视频输入 | 1× ESP32-CAM MJPEG | v6 统一：三通道均默认 MP4，B/C 也可选 MJPEG（多摄像头），A 不再特殊 |
| 检测线程 | 1× `detect_loop()` | 3× 独立检测线程（每通道独立 YOLO 推理） |
| 仪表盘 | 1 个视频窗口 + 单统计卡片 | 3 个视频窗口 + 每通道独立人数/状态灯 + 联动推荐面板 |
| 报警决策 | 单通道三级报警 | 联动决策：排除火灾通道 → 推荐人数最少安全出口 |
| MQTT 协议 | `COUNT:X,ALARM:Y` | 扩展为多通道 + 推荐出口信息 |
| 火焰传感器 | 固定通道 A（ESP32-CAM 对应位置） | v7：跟随 STM32 绑定通道，物理火焰→绑定通道 fire→lv=2→舵机/蜂鸣器自然触发 |
| 舵机 | 单场景控制 | 共享物理舵机，OR 逻辑（任一红色→开） |
| 蜂鸣器 | 单场景报警 | 共享，任一红色即响 |

### 联动决策逻辑（见 `docs/architecture.md`）

```
collect A/B/C: {count, alarm_level, fire}
safe = 排除 fire=true 的通道
if safe 为空 → 全部危险，不推荐
else → 推荐 safe 中 count 最小的通道 ⭐
任何通道 red → 舵机开；全部 green/yellow → 舵机关
火焰传感器固定分配给通道 A（实物限制）
```

### [新发现] 仪表盘应急场景信息层级 (2026-05-16)

当前仪表盘偏常态化监控大屏。应急场景核心需求："哪里着火了？哪里安全？我往哪走？" 三秒内要有答案。

| # | 问题 | 建议 | 状态 |
|---|------|------|------|
| 1 | 推荐面板在中间行，跟控制栏混一起 | 双态：正常低调一行，紧急撑满全宽+大面积色块+大号疏散箭头 | ✅ 已实现 (仪表盘应急模式.md) |
| 2 | 火灾通道标记太弱（仅细红边框） | 火灾通道红框强化，安全通道绿色高亮 | ✅ 已实现 |
| 3 | 折线图应急时无关 | 紧急态自动折叠，恢复时展开 | ✅ 已实现 |
| 4 | 顶部无系统状态大标签 | 加 🟢正常运行 / 🔴紧急疏散 标签 | ✅ 已实现 |
| 5 | 折线图一张 vs 三张 | 维持一张三线，对比效率高于拆分 | ✅ v3 已实现 |

**结论：** 问题不在折线图怎么画，在信息层级。已由 仪表盘应急模式.md 子对话实现（见 `docs/仪表盘应急模式.md`）。

## 当前代码结构

### `detector.py` (261行)

```python
annotated_frame = None
person_count = 0
alarm_level = 0
```

`detect_loop()`（第 57-218 行）：单通道 MJPEG 读取 + YOLO 推理 + 防抖 + MQTT 广播 + DB 写入。

`generate_frames(stop_event=None)`（第 221-261 行）：单通道视频流生成器，~20fps。

关键路由：
- `/video_feed`（第 25-34 行）：单连接去重，调用 `detector.generate_frames()`
- `/dashboard`（第 98-121 行）：合并返回 `status + history + alarms`
- `/control`（第 68-82 行）：手动报警/解除
- `/set_threshold`（第 55-65 行）：动态调阈值

### `templates/index.html` (549行)

- 1 个视频窗口（`<img id="videoFeed">`）
- 4 个统计卡片（当前人数、报警状态、今日检测、报警/峰值）
- 1 个 Chart.js 折线图
- 控制栏（阈值输入 + 手动报警/解除按钮）
- 报警横幅 + 报警历史表格

## 测试方法

```bash
# 1. 准备 2 个 MP4 测试视频（行人场景），放到 campus_monitor/videos/
#    通道 A 使用现有 ESP32-CAM 实时流（不可用时自动回退 MP4）
# 2. 启动系统
cd F:\bishe\campus_monitor
/c/Users/DayMer/miniconda3/python.exe app.py

# 3. 浏览器打开 localhost:5000，确认：
#    - 3 个视频窗口均有画面
#    - 每通道独立计数和状态灯
#    - 调高某通道阈值触发报警 → 联动推荐面板更新
#    - 点击火灾模拟按钮 → 对应通道标记为危险，推荐排除
```

验收标准：
- 通道 A ESP32-CAM + 通道 B/C MP4 三路独立推理，帧率 ≥ 10fps/路
- 联动推荐逻辑正确（火灾通道排除 + 推荐人数最少安全出口）
- 仪表盘 3 窗口 + 推荐面板 + 火灾按钮均正常工作
- MQTT 广播包含推荐出口信息
