# 第7课：数据库 + 钉钉通知 — db.py & notify.py

## 这段代码解决什么问题

- 数据不能只看实时——需要存下来画折线图、查历史
- 报警不能只在屏幕上闪——需要推到手机上（答辩老师可能在别的地方）

## 数据库：两张表

### detection_records — 检测记录（时序数据）

```sql
CREATE TABLE detection_records (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    timestamp   TEXT NOT NULL,        -- ISO格式时间戳 "2026-05-17T14:30:00"
    count       INTEGER NOT NULL,     -- 人数
    alarm       INTEGER NOT NULL,     -- 报警等级 (0/1/2)
    fps         REAL NOT NULL,        -- 帧率
    channel     TEXT NOT NULL DEFAULT 'A'  -- 通道标识
);
```

每秒约写入 3 条（3通道 × 1条/秒），一天运行 ≈ 259,200 条。SQLite 单文件无压力。

### alarm_events — 报警事件（摘要数据）

```sql
CREATE TABLE alarm_events (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    start_time  TEXT NOT NULL,        -- 报警开始时间
    end_time    TEXT,                 -- 报警结束时间 (NULL=进行中)
    max_count   INTEGER NOT NULL DEFAULT 0,  -- 本次报警峰值人数
    level       INTEGER NOT NULL DEFAULT 1,  -- 最高报警等级
    duration    REAL,                 -- 持续时间(秒)
    channel     TEXT NOT NULL DEFAULT 'A'    -- 通道标识
);
```

end_time = NULL 表示报警仍在进行中。一次报警对应一条记录，而不是每秒一条。

### 写入时机

```python
# detector.py detect_loop 内:
insert_detection(count, alarm_level, fps, channel)  # 每秒每条通道1条

# 报警开始:
event_id = start_alarm(max_count, level, channel)   # 返回 event_id
st['alarm_event_id'] = event_id

# 报警结束:
end_alarm(event_id, alarm_max_count)  # 写入 end_time + duration
```

## 数据库查询

| 函数 | SQL | 用途 |
|------|-----|------|
| `get_channel_history(limit, since)` | `SELECT * FROM detection_records WHERE channel=? AND timestamp>? ORDER BY id DESC LIMIT ?` | 折线图数据 |
| `get_recent_records(limit, channel)` | `SELECT * FROM detection_records ... ORDER BY id DESC LIMIT ?` | 最近记录 |
| `get_alarm_events(limit)` | `SELECT * FROM alarm_events ORDER BY id DESC LIMIT ?` | 报警表格 |
| `get_today_stats(channel)` | `SELECT COUNT(*), SUM(alarm>0), MAX(count) FROM detection_records WHERE timestamp LIKE '2026-05-17%'` | 今日统计卡片 |

### since 参数的作用

```python
# 前端在页面打开时记录 PAGE_OPEN_TIME = new Date().toISOString()
```

## 钉钉通知 — notify.py

### 通知类型

| 函数 | 触发时机 | 内容 |
|------|---------|------|
| `alarm_notify(channel, level, count)` | 报警状态确认后 | 哪个通道、几级报警、当前人数、推荐出口、三通道状态表 |
| `alarm_clear_notify(channel, peak)` | 报警解除后 | 哪个通道恢复、本次峰值、其他仍在报警的通道列表 |

### 冷却机制

```python
_COOLDOWN_RED = 30    # 红色报警 30s 内不重复推送
_COOLDOWN_YELLOW = 60 # 黄色预警 60s 内不重复推送
_COOLDOWN_CLEAR = 30  # 解除通知 30s 内不重复推送

# 例外：火灾永远穿透冷却（最高优先级）
# 例外：等级升级穿透冷却（黄色→红色立即推）
```

### 异步发送

```python
def send_notification(title, markdown_text):
    t = threading.Thread(target=_do_send, args=(title, markdown_text))
    t.daemon = True
    t.start()  # 不阻塞 detect_loop
```

### 四种策略的通知文案

```
all_clear:  "所有出口运行正常"（几乎不发，正常状态不推）
guided:     "推荐从出口B（侧门）通行，当前饱和度30%"
degraded:   "全出口接近容量上限，请分批通行"
emergency:  "🔴 全通道火灾告警！请立即疏散！"
```

### 通知内容样例

```markdown
## 🔴 出口A（正门）红色报警
**当前人数:** 25 人 (阈值: 20)
**推荐出口:** 出口B（侧门）— 饱和度 30%

| 通道 | 状态 | 人数 | 饱和度 |
|------|------|------|--------|
| A（正门）| 🔴 | 25 | 125% |
| B（侧门）| 🟢 | 4 | 30% |
| C（后门）| 🟢 | 6 | 50% |
```

## 你答辩时怎么说

> "数据库用 SQLite 存两类数据——每秒的检测记录和报警事件的起止摘要。前端折线图通过 since 参数只拉页面打开后的数据，避免旧数据污染。钉钉通知有 30-60 秒冷却机制防刷屏，但火灾和等级升级会穿透冷却。通知内容是 markdown 格式，根据四种决策策略生成不同的疏散建议文案。"
